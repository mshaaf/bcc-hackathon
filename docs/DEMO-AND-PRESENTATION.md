# Demo and presentation plan

This is a proposed three-minute format, not a verified event presentation limit. Recheck the actual format before final rehearsal.

## Shared structure

| Time | Beat | What the audience should understand |
|---|---|---|
| 0:00–0:30 | One person and one concrete problem | Why this task matters and what is difficult today |
| 0:30–2:00 | The judge makes a consequential choice | The software works and the decision changes the result |
| 2:00–2:40 | Inspect source and finished artifact | The result can be checked and an uncertain case stays honest |
| 2:40–3:00 | One useful finish and next validation step | What the person can now do and what remains to prove |

Use three sparse slides: the problem, the live decision, and the result. Spend the middle inside the product. Presenter A establishes the person and narrates; Presenter B operates the product and opens the artifact. Swap only if that makes rehearsal smoother.

## Six possible stage moments

| Project | Opening line | Judge action | Reveal and finished artifact |
|---|---|---|---|
| Block Ops | “We have several ticket numbers and a meeting tomorrow.” | Inspect and reject a report from another site; choose the next request. | Timeline/source appendix change; open the group's brief and two-task plan. |
| The Switch | “Same person. Same qualifications. What survives the summary?” | Switch reviewed wording and demand the source for a claim. | Open exact supporting words, applicant approval, and a reproducible receipt. |
| Casebreaker | “One case. Two stories.” | Follow a disputed entry and inspect both original pages. | Pending versus Dismissed becomes a precise reviewed request; an ambiguous match stays unresolved. |
| The Room | “I want to leave knowing what happens next.” | Choose a goal, retry, or supporter role. | The card preserves the original concern and preferred question. |
| Reclaim | “An old record may matter today.” | Select the source value, then open the undated report. | Confirmed evidence and missing-record questions appear in the transplant-team packet. |
| People's Chamber | “Chair, give me the floor.” | Play the practice chair and ask for a specific action. | A vague request becomes a focused resident-owned statement. |

The full product pictures and pitches are in [FINALISTS.md](FINALISTS.md). The portable preview provides Opening / Live demonstration / Closing storyboards for all six.

## Proof beats

- Show actual output regeneration after the judge's choice.
- Open at least one original source, not just an AI explanation.
- Show one deliberate uncertainty or rejected relationship. Explain it in plain language.
- End on the readable brief/card/summary/statement/packet, not a loading screen.
- Name measurements actually collected. A polished mockup or labeled fixture is not measured downstream impact.

For The Switch, prepare an honest passing-result branch. A recorded model run must show its date and replay status. The current deliberately reversed availability claim is a checker example; never present it as a model finding.

## Stage reliability

Keep a local dated cache or synthetic fixture path where appropriate. Label it correctly. A short backup recording can preserve the presentation if a network dependency fails, but should not be presented as a live run. Test the stage browser, display scale, output opening, and any required network before judging.

Only request one clear judge action. Keep the interaction safe to reverse, explain the expected choice briefly, and retain a presenter-operated path if the judge prefers to watch.
