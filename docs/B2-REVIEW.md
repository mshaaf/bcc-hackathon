# B2 independent review — findings and resolution

Review of HEAD `f03cd46` (backend `a53f3c0`). Verdict: the web app and mission loop are real; four verified gaps and three app-experience issues needed repair before deployment. The original review text is kept outside the repository; this file tracks what each finding needed and where it stands. **Code and tests for every item are in the B3 repair batch; the items that need the real backend are marked unverified until that stack is allowed to run** (see [PHASE-STATUS](PHASE-STATUS.md)).

| # | Finding | Fix | Evidence now |
|---|---|---|---|
| 1 (P1) | A malformed imported record (`id` as an object with null `toString`/`valueOf`) made `normalizeEvidence` throw, so `listMissions` failed and the whole community stopped loading for other members. | **Write boundary:** `create_mission` validates source, every evidence field's type and length, observation shape and size (migration `20261022100000`). **Read side:** `normalizeEvidence` coerces every field to a plain primitive; `normalizeRows` drops a row that still fails instead of failing the list. | Unit: the old code threw "Cannot convert object to primitive value" (confirmed), the new code returns unknowns; hostile record exports without error. **Backend: written, not run.** |
| 2 (P1) | A claimant could finish a job, leave the mission, then reopen it (`set_task_done(false)`) and hold an unfinished job as a non-member; the organizer could do the same on their behalf. | `set_task_done` now takes membership locks before the task lock (same order as `claim_task` and `leave_mission`), requires a non-organizer actor to still be a mission member, reopens a departed claimant's job as **unclaimed**, and re-checks the claimant after the lock. | **Migration parses (syntax only); behavior tests written, not run.** |
| 3 (P2) | UI said "Done · reported by <claimant>" even when the organizer marked it done. | Claimant shown separately, neutral "Reported done" (the backend stores no reporter). | Unit + interface check (fake backend). |
| 4 (P2) | Add job cleared newer description/due drafts unconditionally after the request returned. | `sendJob` clears only the text that was sent, bound to the community the form belonged to. | Unit regressions (typing during a pending save, failure keeps text, navigation) + interface check; the check fails when the old unconditional clear is restored. |
| — | New-mission validation errors stayed after the field was fixed. | Each field re-validates as it is edited and drops its own error and `aria-invalid`. | Interface check. |
| — | No route back to the originating discussion post. | Mission header shows the source excerpt and a link that opens the feed at that post and focuses it (`#/community/<id>?post=<id>`). | Interface check. |
| — | Remote changes not announced; second job action lost focus; routed screens had no destination focus. | Plain-language announcements for others' claims, releases, completions, joins, leaves, new jobs and organizer edits; every job action has its own focus key; navigation moves focus to the screen's heading and titles the page. | Unit + interface check. |

Still open from the review: screen-reader testing, Safari/Firefox, a fresh real-phone test, hosted deployment, anonymous-auth abuse controls ([DEPLOYMENT](DEPLOYMENT.md)).
